# 공통 작업 절차

사용자 지시가 우선이다. [최신 BLOOM 공통 규칙](https://raw.githubusercontent.com/byh-playground/bloom-reference/main/AGENTS.md)을 읽고 그 정책을 적용하며, 이 파일은 여러 개발 대화가 함께 일할 때의 운영 경계만 보충한다. 제품·브랜치·머지 방식은 대상 저장소의 `AGENTS.md`에서 읽는다. 규칙 원문을 여기 복제하지 않는다.

- 의도·정상/반례·관찰·검증은 AI-001~AI-007·AI-013~AI-017, 버전·PR·배포·문서 동기화는 PM-001~PM-012를 따른다. 조회 실패와 미검증 범위를 숨기지 않고 실제 한 일만 보고한다.
- 성능에 닿는 작업은 AI-019의 알고리즘 레퍼런스와 기존 기록부터 읽는다. 비용 변화의 예상과 실측을 구분하고 발견·미확인 사항을 PR에 기록한다. PM-014에 따라 정합성 게이트와 성능·부하 측정은 별도 실행으로 분리한다.

## 담당과 PR 본문

- 착수 전에 열린 PR의 본문·관련 댓글·실제 diff, 현재 브랜치·worktree·미커밋 변경을 확인한다. 조회 실패를 진행 작업 없음으로 해석하지 않는다. 담당이 여러 후보와 겹치면 경계를 확인하고 다른 담당자의 변경을 보존한다.
- 업무의 의도·담당 대화·현재 상태는 PR 본문을 SSOT로 관리한다. 개발 계약은 프로젝트 원본에 두고 같은 계획을 별도 인벤토리·계획 파일에 복제하지 않는다. 본문은 문제와 결과가 이어지는 문장으로 쓰며, 예상하기 어려운 실패 경로·의존성과 중요한 미검증 사항을 담는다.
- 등록만 요청한 업무는 Draft PR의 대기 상태로 두고 구현·머지 권한으로 확대하지 않는다. 배정할 때 PR·브랜치·worktree 절대 경로·담당 대화를 본문에 기록하고 실제 착수가 확인된 뒤 개발 중으로 바꾼다. 인계 대상과 범위는 사용자가 정한 지시를 따른다.
- 현재 의도·담당·상태는 본문을 갱신하고, 착수·인계·변경 이유 등의 이력은 댓글에 남긴다. GitHub 댓글 게시 등 외부 메시지는 사용자가 요청했거나 명시적으로 적용한 스킬이 허용한 범위에서 수행한다.

## 변경 격리와 통합

- 수정은 같은 Git 공통 디렉터리를 공유하는 별도 worktree에서 수행한다. 실제 경로·브랜치·`git rev-parse --git-common-dir`를 배정과 비교한다. 읽기 전용 조사에는 새 worktree가 필요하지 않다. 주 작업 폴더는 조회·통합 브랜치 동기화에 사용하고, 독립 clone이나 주 폴더의 브랜치 전환으로 격리를 대신하지 않는다.
- 병렬 수정자는 각각 worktree를 사용하고 같은 PR의 통합·커밋·푸시는 한 담당이 소유한다. 파일·줄뿐 아니라 함수·스키마·상태 소유자·공통 계약·호출 관계로 겹침을 판단한다.
- 미머지 작업에 의존하는 후속 변경은 같은 담당 PR에 반영한다. 이미 머지된 작업의 후속은 최신 통합 브랜치에서 시작한다. 실제 충돌·행동 간섭을 확인하기 전에는 독립성을 확정하지 않는다.
- 검증 후 본문을 실제 결과에 맞게 갱신하고 Draft를 해제한다. 머지·정리·공개 확인은 프로젝트 절차를 따르며, 미반영 변경·진행 worktree·앱 소유 복구 참조를 임의 삭제하지 않는다.
