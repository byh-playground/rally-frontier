# 공통 작업 지침

이 파일은 저장소 이름·브랜치·언어·제품 구조를 고정하지 않는 공통 운영 규칙이다. 대상 프로젝트의 `AGENTS.md`가 이 파일을 참조할 때 읽고 적용한다. 사용자 지시가 우선하며, 프로젝트 지침은 통합 대상·브랜치 규칙·커밋 언어·개발 판단 기준·검증 및 머지 절차를 구체화한다.

- 포괄적인 단어보다 의도를 표현하는 좁고 구체적인 단어를 사용한다.
- 저장소 변경은 통합 브랜치에 직접 커밋하거나 푸시하지 않고 작업 브랜치에서 진행한다. 필요한 검증과 커밋·푸시를 마치고 기존 PR을 갱신하거나 새 PR을 만든다. 사용자가 PR의 Files changed에서 변경을 리뷰할 수 있어야 완료다. PR은 호스팅 서비스의 Merge Request도 포함한다.
- 실제 수행한 검증 결과와 중요한 미검증 사실을 정확히 전달하고, 완료 응답에는 PR 링크와 검증 결과를 제공한다. 푸시나 PR 생성이 실패하면 완료로 보고하지 않고 장애와 남은 작업을 알린다. 검증하지 않은 결과를 검증 완료 또는 Stable로 표시하지 않는다.
- 사용자의 명시적 머지 지시 없이 PR을 머지하지 않는다. 등록·배정·푸시 요청을 머지나 공개 배포 지시로 해석하지 않는다. 머지 방식과 완료 후 정리는 대상 프로젝트의 절차를 따른다.

## PR 본문을 업무 SSOT로 사용

- 개별 업무의 의도·현재 담당·진행 상태는 PR 본문을 SSOT로 관리하고, 같은 내용을 별도 계획 파일이나 공용 인벤토리 파일에 복제하지 않는다. 장기 제품·개발 계약은 프로젝트가 정한 원본을 따른다.
- 개발 또는 개선 등록 전에 열린 PR과 관련 본문·댓글·diff를 조회한다. 진행 대화·브랜치·worktree·미커밋 변경도 가능한 범위에서 확인한다. 조회 실패를 작업 없음으로 간주하지 않는다.
- 담당 작업은 사용자가 지정한 PR과 현재 브랜치의 PR으로 확인한다. 서로 다르거나 여러 후보가 있으면 담당을 확인한다. 배정 없는 개발 대화는 대기 업무를 임의로 맡지 않는다. 사용자가 새 개발을 지시했다면 겹침을 확인하고 새 PR로 등록한다.
- 관리 대화는 개선을 먼저 등록하고 개발 대화가 이어 구현하는 동안 다음 독립 항목을 찾는다. 최신 통합 브랜치에서 독립 항목마다 별도 작업 브랜치와 Draft PR을 만든다. 구현 전 등록에 빈 커밋을 사용할 수 있지만 계획 파일이나 가짜 코드 변경을 만들지 않는다. 등록한 Draft PR은 개발 완료가 아니다.
- 본문은 문제의 원인과 개선 의도가 잘 전달되는 문장으로 쓴다. 기대 동작·작업 범위·완료 조건·검증 계획 등의 항목 구분이나 고정 템플릿은 사용하지 않는다. 개발 인계에 필요한 경계와 의존성은 문장에 자연스럽게 설명한다.
- 당연한 검증 조건이나 관행적인 체크리스트는 반복하지 않는다. 예상하기 어려운 실패 경로·회귀 위험이나 특별히 확인해야 하는 동작을 발견했을 때 이유를 적는다. 이는 실제 검증을 생략하거나 미검증 사실을 숨기라는 뜻이 아니다.
- 담당 대화 ID 또는 링크와 상태를 짧게 남긴다. 담당이 없으면 미배정으로 표시하고 대기·개발 중·검증 중·리뷰 대기를 구별한다. 계정 assignee나 Draft 상태만으로 대화별 예약이 보장된다고 가정하지 않는다.
- 현재 의도·담당·상태는 본문을 갱신하고, 착수·인계·변경 이유·장애 등의 이력은 댓글에 남긴다. 댓글에서 범위를 바꿨으면 본문에도 반영한다. PR의 내용은 사용자와 프로젝트가 승인한 업무 범위에서 해석한다.
- 병렬 작업은 별도 worktree 또는 체크아웃을 사용하고 다른 개발 대화의 브랜치나 미커밋 변경을 보존한다. 파일명이나 줄 겹침만으로 독립성을 판단하지 않고 함수·모듈·스키마·상태 소유권·공통 계약과 호출 관계를 확인한다.
- 후속 업무가 미머지 A의 구현에 의존하면 A의 본문에 반영해 같은 담당 대화가 같은 브랜치에 추가 커밋하도록 인계한다. A가 통합 브랜치에 머지됐다면 최신 통합 브랜치에서 새 PR을 만든다. 목적은 다르지만 같은 내부를 수정해야 하면 경계를 분리하거나 보류한다.
- 독립 PR은 다른 미머지 PR 없이도 구현·검증·머지할 수 있어야 한다. 등록 때는 예상 의존성을, 리뷰 준비 때는 최신 통합 브랜치와 관련 열린 PR에 대한 실제 병합 충돌·동작 간섭을 확인한다. 확인한 기준 커밋과 조합, 실제 검증 결과와 중요한 미검증 사항을 본문에 남긴다. 병합 충돌이 없다는 사실만으로 동작 독립성을 선언하지 않는다.
- 구현과 필요한 검증을 마친 뒤 본문을 최종 변경에 맞게 갱신하고 Draft를 리뷰 가능 상태로 전환한다. 계획과 실제 결과를 구별한다.
