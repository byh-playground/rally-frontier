## Runtime and checkpoint representation

`StrategySim` owns canonical route bodies in `routePathStore`, with separate profile and topology tables. A unit's movement state stores only route handles (`pathId`, `cursor`, `legX`, `legY`, `retained`). Checkpoints serialize path rows as `[id, profileId, topologyId, exactFlatPoints, tailId, tailStart]`, plus deduplicated profile and topology rows. A joined route keeps its local prefix and a root path ID/offset for the shared suffix; it does not copy that suffix. Coordinates stay exact and are not quantized.

The published PR head (SIM194, `1ab217c`) instead stored each unit's route rows with its own `{key, radius, ignore, points, topology, cursor, legX, legY, retained}` object. SIM198 removes repeated per-unit path points and repeated profile/topology data from saved state.
