## 변경과 비용

공통 MovementComponent가 경로 이력(최대3개)과 활성 인덱스·cursor를 소유한다. 획득 때만 같은 목표·반경·통행 정책의 suffix에 안전한 직선 합류를 시도한다. 시작 셀 일치나 임의 합류 거리 상한은 요구하지 않는다. 이력이 경로 획득 뒤 한 번도 이어 쓰이지 않았다면 다음 목표 전환에서 버린다. 정상 이동은 활성 leg를 쓰고, 가까운 corner의 인접 연결 하나와 도착 영역은 국소 물리 sweep으로 확인한다. 전체 suffix 가시성 검사나 경로 cache 획득은 하지 않는다. 유닛별 좌표 복사는 남아 있으며 전역 경로 좌표 dedup pool을 구현한 것은 아니다.

도착 영역은 실제 상호작용 범위를 바꾸지 않는다. 가까운 도착 구간에서 경계만 향한 짧은 이동이 separation에 상쇄되던 현상은 검증된 내부점으로 이동 의도를 유지해 고쳤다. 실제 상호작용 판정이 만족되면 기존 작업/공격 로직이 멈춘다. 일꾼 수입·시간·반경·이동속도·충돌 반복 횟수·SDK는 바꾸지 않았다. 경로·cursor와 목표 이력은 권위 snapshot이며 후보 인덱스는 runtime epoch/현재 유닛 배열에 묶어 복원한다. 중복 통행 프로필을 key에 다시 직렬화하지 않으며 SIM192·중간 SIM193 snapshot/리플레이와 호환되지 않는다.

512점 일꾼 전용 한도는 공통 checkpoint 배열 예산20000점과 통합했다. 600점 경로의 활성 handle 유지 검사가 있다. 공통 checkpoint 예산 밖의 극단 경로는 기존 transient fallback이며 무조회 보장 검증 범위 밖이다.
