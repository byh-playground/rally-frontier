# 쌀콩팡! · Rice, Beans & Boom!

쌀·조·콩·팥·밤톨·옥수수·도토리 병력을 대포로 투입하고 거점을 건설·점령하는 브라우저 전략 게임입니다. 병력 투입과 진영 공통 발사 사거리 강화에 같은 자원을 사용합니다. 싱글은 AI와, 친구 대전은 실제 WebRTC P2P로 플레이하며 결과·리플레이를 확인할 수 있습니다.

조는 이삭 한 발을 175원에 쏘아 체력 15·공격력 8인 병사 20명을 같은 틱에 착점 중앙부터 바깥까지 사방으로 투입합니다. 이삭의 착탄 피해는 10, 범위 반경은 50입니다. 병사는 적을 추적하거나 공격하지 않을 때 기본 이동속도의 두 배로 이동합니다. 실제로 부딪힐 때만 피해를 주고 뒤로 물러났다 다시 돌진합니다. 착탄 주변에 20명이 모두 들어갈 공간이 없으면 병력을 잃지 않고 묶음째 기다렸다가 재시도합니다.

옥수수는 후방에서 알을 던지며, 알은 지면에 처음 닿은 후 1초 뒤 폭발합니다. 투입은 옥수수 콘 한 발에 6명이며, 알의 높이와 지상 충돌은 권위 시뮬레이션이 처리합니다.

도토리는 비용 375로 세 발을 발사해 세 명을 투입하며 체력은 75입니다. 회전 공격은 지상 적 한 명에게 타격당 피해 13을 주며 밀어냅니다.

찹쌀은 식량 100·기름 25로 5명을 투입합니다. 땅콩처럼 건물로 돌진하다가 완공된 적 전진 거점에 닿으면 한 명이 포구를 1초 동안 감싸고, 그동안 그 거점의 대포 발사와 포탑 공격이 멈춥니다(생산은 계속). 한 거점에는 한 명씩 붙으며 붙었던 병사는 5초 뒤 다시 붙을 수 있습니다. 캠페인 보상 없이 처음부터 덱에 넣을 수 있습니다.

감자는 식량 25·기름 75로 대포마다 한 알만 발사하며 최대 사거리는 다른 병력의 75%입니다(일제사격은 참여 대포마다 한 알, 비용은 한 번). 떨어진 감자는 땅을 파고(0~2초) 뿌리를 내린 뒤(2~4초) 5초 만에 전진 대포가 되고, 그 전에 쓰러지면 대포는 생기지 않습니다. 전진 대포는 거점 대포와 같은 재장전·비용으로 병력을 발사하지만 포탑·생산·점령은 없으며, 체력 150이 초당 10씩 줄고 적 피해도 받습니다. 처음부터 덱에 넣을 수 있습니다.

대전 전에 덱을 편성해 가져갈 병종을 선택할 수 있습니다. 편성 화면에서 병종의 역할·투입 비용과 인원·특징을 비교할 수 있습니다. 덱 3개는 기기별로 저장되며, 경기 시작 시 양쪽 덱이 확정되어 발사 판정과 리플레이에 반영됩니다. 현재 `콩` 병종의 공통 식별자는 버드모리와 같은 `pea`입니다.

경기 결과의 병종별 출격은 발사 승인 수가 아니라 실제로 생성된 병사 수입니다. 병종별 처치는 적 병사만 세며, 유효 피해는 적 병사와 건물의 실제 감소 체력을 합산해 초과 피해를 제외합니다. 해당 병종의 투입 포탄 피해와 병사 공격을 함께 집계하고 병종이 없는 건물 자체 공격은 제외합니다. 이 누적치는 경기 권위 상태에 보관되어 스냅샷·복구·리플레이에 포함됩니다.

영문 표기는 **Rice, Beans & Boom!**입니다. 링크 공유에는 가로 썸네일 [`assets/ssalkongpang-thumbnail.png`](assets/ssalkongpang-thumbnail.png)을 우선 사용하고, 정사각형 시안 [`assets/ssalkongpang-thumbnail-square.png`](assets/ssalkongpang-thumbnail-square.png)도 Open Graph에 제공합니다. 실제 이미지 선택은 공유 서비스에 따라 다릅니다. BLOOM PLAYGROUND 매니페스트의 영문 필드는 해당 스키마의 문자 제한 때문에 `RICE BEANS AND BOOM`으로 표기합니다.

쌀·조·콩·팥·밤톨·옥수수·도토리는 승인된 몸체와 얼굴·팔다리 스프라이트를 공통 아틀라스와 GPU 포즈로 조합합니다. 대포는 벡터 원본을 사용합니다. 앱 아이콘은 승인된 정사각형 공유 썸네일을 원본으로 사용하며, 원본 변경 후 `npm run generate:icons`로 180·192·512px 아이콘을 다시 만듭니다. 아이콘 원본 변경 시 manifest와 HTML의 아이콘 URL 캐시 식별자도 갱신합니다.

## 버전과 배포 출처

| 식별자    | 원본과 의미                                                                                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 게임 버전 | [`PRODUCT_VERSION`](src/core/product-version.js)의 SemVer 한 값이 화면·배포 기록·방 발견·세션·snapshot·리플레이의 공통 원본입니다. 게임 호환성은 이 문자열의 정확한 일치로 판정합니다. |
| 배포 출처 | `_site/build.json`의 Git 커밋·복사 시각·SDK 출처. 실행 모듈 bytes 일치 검증이나 제품 버전·Stable 승격의 증거가 아닙니다.                                                               |

제품 버전 판단은 [최신 공통 PM-001·PM-002](https://github.com/byh-playground/bloom-reference/blob/main/AGENTS.md)를 따릅니다. 제품 세대 전환은 MAJOR, 비호환 변경은 MINOR, 호환되는 의미 있는 기능·표현 수정은 PATCH입니다. 외부 동작이 같은 내부 정리와 문서 정리는 버전을 유지합니다. 하드코딩된 유닛·발사 수치 변경이 동일 입력의 결과나 과거 리플레이 해석을 바꾸면 호환되는 밸런스 수정으로 분류하지 않습니다. 게임 MINOR를 올리며 별도의 시뮬레이션 버전은 관리하지 않습니다.

사용자 지시에 따라 게임 버전 하나를 호환성의 SSOT로 사용합니다. `0.1.0`은 기존 SemVer가 없던 제품의 첫 기준선이며, `0.2.0`은 게임 규칙·저장 및 통신 계약의 비호환 변경을 반영합니다. 과거 내부 카운터에서 제품 이력을 역산하지 않으며, 버전 갱신이 정식 출시나 Stable 승격을 선언하지 않습니다. 고정 SDK의 버전·source/dist 커밋·해시는 [`gamekit.lock.json`](gamekit.lock.json)이 관리합니다.

`0.3.0`부터 방 발견 namespace와 리플레이 프로토콜을 쌀콩팡 이름으로 교체합니다. 이전 버전과는 방을 함께 찾거나 리플레이를 열 수 없으므로 두 플레이어가 모두 최신 버전으로 새로고침해야 합니다.

`main` 푸시는 Pages 배포와 Nightly 태그 생성을 유발합니다. Stable은 PM-005에 따라 검증·승인한 커밋을 [release-tags 워크플로](.github/workflows/release-tags.yml)에서 명시 승격한 불변 태그입니다. 제품 버전·빌드 성공·배포 시각·게임 검증·Stable을 서로 구별합니다.

## 현재 플레이

- 캠페인에서 보상 병종을 적으로 먼저 만나고, 스테이지를 처음 클리어하면 해당 카드를 대전 덱에 장착할 수 있습니다. 캠페인 편성은 스테이지마다 고정됩니다. 처음 배치된 적 수비대는 제자리를 지키고, 기름 병종을 쓰는 적 스테이지에는 적의 기름 거점이 있어 그 병종이 계속 나옵니다. 캠페인은 기초·기본 병종·중급 병종·고급 병종 네 단계이며 선택 화면에서 단계를 눌러 펼치는 목록으로 고릅니다. 한 단계 안의 스테이지는 순서 없이 고를 수 있고 앞 단계에서 하나만 깨면 다음 단계가 열립니다. 이 브라우저에 저장된 클리어 기록으로 카드 해금을 판정하며, 저장된 대전 덱에서도 해금한 카드만 불러옵니다.
- 각 플레이어는 살아 있는 병사와 이미 발사한 병력을 합쳐 300명 이상이면 새 병력을 발사할 수 없습니다. 300명 미만에서 시작한 발사는 인구 한도 때문에 병력을 줄이지 않습니다.
- 쌀은 5갈래 산탄, 조는 이삭 단발, 콩은 단발 중심 강타, 팥은 같은 지점에 3연사, 밤톨과 옥수수는 각각 한 발로 병력 한 묶음을 보냅니다. 도토리는 한 명씩 세 발을 발사합니다. 전장을 길게 눌러 거리를 조절하고 놓으면 발사하며, 너무 오래 누르면 과열됩니다.
- 시작 자원은 250원, 한도는 500원이며 기본 인컴은 초당 15원, 완성한 점령지마다 초당 5원이 더해집니다. 병력 투입 비용은 쌀 125원·조 175원·콩 250원·팥 250원·밤톨 250원·옥수수 250원·도토리 375원입니다. 진영 공통 최대 발사 거리는 쌀 기준 500→1,000→1,500, 강화 비용은 250원·375원입니다. 조·콩·밤톨·옥수수·도토리는 85%, 팥은 75% 비율을 적용합니다. 완성한 아군 대포의 원은 선택 병종의 최대 발사 거리입니다.
- 중립 거점에 한쪽 병력만 진입하면 체력 10%로 공사를 시작합니다. 거점은 75원·375작업이 필요하고 일반 유닛은 몸통 박치기가 닿을 때마다 1작업을 더합니다. 비용·필요 작업량·타격당 작업량은 독립 설정입니다. 전체 작업 진행률·투입 자원과 다음 정수 지출까지의 5칸을 구분해 표시합니다.
- 누적 지출은 `floor(cost * workDone / workRequired)`입니다. 자원이 1원 이상일 때 기본 거점은 첫 4작업까지 추가 지출이 없고 5작업마다 1원이 듭니다. 자원이 0원이면 지출이 없는 타격도 포함해 작업을 멈춥니다. 여러 작업자는 각자 기여하고 최종 적중은 남은 작업까지만 처리합니다.
- 작업자는 건설을 우선합니다. 실제 피해를 받으면 닿는 적에게 응전하고, 닿는 적이 없으면 건설을 재개합니다. 이탈·사망·교전·공중 이동·충격 회복 중에는 작업량이 늘지 않습니다. 누적 공사와 피해는 보존되며 파괴된 투자금은 환불하지 않습니다. 완공하면 소유·인컴·발사와 사거리 250의 단일 기본 공격(피해 10/초)이 활성화됩니다.
- 강 위의 병사는 이동 속도가 절반이고 받는 피해가 1.5배이며 다리 위는 예외입니다. 경사로를 오를수록 이동이 느려집니다. 낮은 곳에서 높은 곳을 향한 일반 원거리 공격은 50% 확률로 빗나가지만, 대포 착탄과 옥수수 폭발은 이 빗나감의 대상이 아닙니다.

조작 설명은 인게임 도움말, 실제 수치는 [`LaunchRules`](src/sim/launch-rules.js)·[`ConstructionRules`](src/sim/construction-rules.js)·[`Definition`](src/definitions/)이 원본입니다.

## 원본과 실행

메인 전투는 독립된 실제 시뮬레이션을 GameKit scenario로 진행한다. `assets/title-showcase.json`은 seed 12349의 한 경기에서 저장한 세 상태이며, 최대 사거리와 연출용 식량을 적용했다. `PRODUCT_VERSION`이 바뀌면 `npm run generate:title-showcase`로 현행 엔진의 상태를 다시 만들고 화면을 검증한다. 빌드는 상태의 게임 버전이 현재 제품 버전과 다르면 실패한다.

시뮬레이션 시간 변환과 상태 codec, 통계 기본값은 UI와 독립된 `src/core/simulation-timing.js`, `src/core/rally-state-codec.js`, `src/diagnostics/simulation-stats.js`가 소유한다. 타이틀과 병종 소개는 준비된 쇼케이스 렌더러를 공유하고 장면마다 독립 시뮬레이션을 실행한다. 실제 대전의 AI 세션은 Worker에서 실행한다.

```text
index.html                 브라우저 ESM 진입점·UI·프로젝트 개발 계약
src/main.js                화면·입력·실제 WebGL renderer
src/core/                  제품 버전·호환 식별자·SDK 로딩·배포 정보
src/definitions/           유닛·건물·전투 수치
src/sim/                   권위 판정·지형·이동·충격·건설
src/session/               경기·명령·리플레이 조정, 워커 호스트·프록시
src/render/                보간 상태·표시 효과·곡물 방출·분할 대포 아트
src/ui/                    자원 HUD·쇼케이스·화면 전환
src/audio/                 효과음 재생
assets/units/              원본 SVG·크기와 SHA-256 manifest
scripts/                   SDK 준비·원본 복사·고정 시나리오 검사
legacy/                    현재 실행·배포에서 제외한 과거 코드 보관소
```

저장소를 정적 HTTP 서버로 제공하면 빌드 없이 실행할 수 있습니다. 예: `python -m http.server 8000` 후 `http://localhost:8000/`. `file://` 실행이나 단일 HTML 오프라인 실행을 보장하지 않습니다. 최초 제품 부팅은 lock으로 고정한 CDN에 접속합니다.

`npm ci`와 `npm run setup:gamekit`은 Node 22 이상에서 QA 의존성과 검증한 SDK cache를 준비합니다. `setup:gamekit`은 불변 dist·manifest·사용 모듈의 SHA-256을 검사하고 Git 제외 `.cache/gamekit/`에 원본 bytes를 저장합니다. 정상 cache는 재사용합니다.

`npm run build`와 [Pages 워크플로](.github/workflows/pages.yml)는 같은 원본 검사·복사 도구를 사용합니다. 실행 원본과 원본 자산을 `_site/`로 복사하며 SDK를 번들링하거나 소스를 재작성하지 않습니다. 실제 복사 목록은 [`build-pages.cjs`](scripts/build-pages.cjs)가 소유합니다. 검사·복사에 실패하면 이전 `_site`를 새 결과로 오인하지 않도록 제거합니다.

시작 로딩의 진행률은 GameKit `boot`가 맡습니다. [`src/core/gamekit.js`](src/core/gamekit.js)가 단계와 가중치를 정하고, 게임 모듈·유닛 그림·병종 스프라이트는 실제 완료 개수를 보고합니다. 고정 SDK는 `boot.importPinnedModules`가 받아 SHA-256을 검증한 뒤 import합니다. 그래픽 준비와 타이틀 장면은 개수가 없어 끝날 때 채워집니다. 모듈이 실행되기 전에는 `index.html`의 짧은 스크립트가 브라우저가 실제로 받은 게임 소스 파일 수와 용량을 표시하고, 로딩 아이콘은 메인 스레드가 막힌 동안에도 도는 transform 애니메이션입니다. 모듈이 실행되기 전에는 `index.html`의 짧은 스크립트가 브라우저가 실제로 받은 게임 소스 파일 수와 용량을 표시하고, 로딩 아이콘은 메인 스레드가 막힌 동안에도 도는 transform 애니메이션입니다. 준비에 실패하면 같은 진행 상태를 재사용하지 않고 페이지를 다시 불러옵니다.

화면의 배포 기록은 `build.json`을 페이지당 한 번, `cache: no-store`·3초 제한으로 읽습니다. 조회는 게임 시작을 막지 않으며 `pending`·`available`·`unavailable`을 구분합니다. 기록이 없거나 실패했다고 공개 게임을 미배포 개발본이라고 판단하지 않습니다. 제품 버전은 로딩한 원본 `PRODUCT_VERSION`을 유지하며, 배포 기록의 제품 버전이 일치하지 않으면 그 기록을 `unavailable`로 판정합니다. 초기 SDK 실패 진단에도 조회가 끝난 배포 정보를 반영합니다.

## 판정·표현·네트워크 경계

프로젝트 고유 계약은 [`index.html` 상단](index.html)에 둡니다. `StrategySim`·`StateContract`가 판정·저장·복원·체크섬을 소유하고, UI·렌더·캐시는 판정을 바꾸지 않습니다. 건설의 인스턴스 설정·작업 단계, 충격 운동과 방출 대기열, 진영별 사거리 레벨도 저장·복원합니다. 건설 중에는 진행률에 따라 공사 틀, 받침, 포가, 포신이 순서대로 나타납니다.

`UnitMotion.applyImpulse`는 `Δv=J/mass`를 기존 속도에 누적합니다. 실제 접촉 시각에서 법선·역질량으로 속도를 처리하고 남은 시간도 적분합니다. 목표 좌표로 밀어내거나 기존 외력을 덮지 않습니다. 공간이 막힌 병력 방출은 안전한 자리가 생길 때까지 보존합니다. 공통 박치기와 목재 틀·묶음 파편은 권위 상태/사건을 읽는 표현입니다.

SVG는 원본 manifest의 SHA-256 검증 후 고정 GameKit 로더가 시작 시 한 번 컴파일하고 cache를 재사용합니다. 프레임마다 SVG를 읽거나 생성된 메시를 배포하지 않습니다. 공통 표시 시계가 위치·높이·생성/제거·VFX endpoint를 샘플링하며 실제 판정 좌표는 유지합니다.

`GameSession`은 SDK의 Core·게임 Adapter·Transport를 조합합니다. SDK의 필수 `simulationVersion` 옵션에도 게임 버전 `PRODUCT_VERSION`을 직접 전달하며 별도 값을 관리하지 않습니다. 명령은 UI와 AI 모두 `GameSession.command(action)`에 제출하고, Core가 player-local sequence의 확정 입력을 게임 틱에 적용합니다. Core frame `t`는 step 이전 상태 `S[t]`입니다. 게임이 입력 지연·롤백·해시·복구를 다시 구현하지 않습니다.

브라우저는 `GameSession`의 시작·종료·오류 콜백에 화면과 백그라운드 틱 처리를 연결합니다. AI는 `src/sim-worker.js`에서 워커 호스트를 불러오고 자체 타이머로 같은 세션을 실행합니다. 워커는 DOM이나 화면 진입점 없이 시뮬레이션, 리플레이 기록, 세션 통계에 필요한 GameKit 모듈을 로드합니다.

현재 게임 버전이 없거나 다르면 연결·snapshot 복원·리플레이 재생을 거부하며 구버전 별칭이나 숫자 변환으로 허용하지 않습니다. 파일 종류·codec 형식의 검증은 게임 호환 버전 관리와 구별합니다.

기본 netcode는 lockstep이며 `?netcode=lockstep|rollback`은 다음 경기의 모드를 고릅니다. 친구 대전의 참가자는 방장이 보낸 동기화 모드를 경기 시작 전에 적용합니다. Nostr는 발견·협상, gameplay는 실제 RTCDataChannel의 바이너리입니다. 별도 게임 서버나 TURN fallback은 없습니다. 방 코드는 실제 Nostr 신호 준비와 코드 확보가 끝난 뒤 표시합니다. 방 준비 취소는 진행 중인 연결도 종료하고, 재시도는 새 방을 만듭니다. 첫 시작 메시지를 보내지 못하면 방장은 시뮬레이션을 시작하지 않으며 재연결한 참가자의 HELLO에 시작 정보를 다시 보냅니다. 싱글도 같은 실제 WebRTC·Session을 쓰며 AI 세션은 Worker에서 실행합니다. 양쪽 세션 관찰용 UI 검사는 in-page AI를 사용하고 Worker 경로는 별도로 검증합니다.

## 검증과 개발

Prettier 설정은 공통 DEV-028을 따릅니다. `npm ci` 후 `npx prettier --write <파일>`로 수정한 파일을 포맷합니다. PR에서는 변경 파일만 포맷·문법 검사하며 테스트는 CI에서 실행하지 않습니다. `npm run format:check`는 기존 파일을 포함한 전체 점검용입니다.

공통 완료·검증·PR 규칙은 [AGENTS.md](AGENTS.md)와 [최신 BLOOM 규칙](https://github.com/byh-playground/bloom-reference/blob/main/AGENTS.md)을 따릅니다. 게임 동작·시각 변경은 실제 플레이 UI 경로와 렌더 관찰을 포함하고, 문서·메타데이터 변경은 해당 범위의 정합성을 검사합니다. PM-009의 실행당 180초, PM-014의 정합성 게이트를 지키며 성능·부하는 별도 명령·실행으로 측정합니다.
